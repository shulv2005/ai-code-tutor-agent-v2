# 错题本 + 举一反三：设计与数据流

> 本文对应需求「右侧分析结果面板改为上下分栏，并新增错题本 + 举一反三」。
> 实现落在本项目现有的 FastAPI + SQLAlchemy(async) + 原生 JS 前端上，
> 没有引入新的框架或依赖。

---

## 1. 技术选型（先回答"后端未定、数据库未定"）

| 层 | 选型 | 为什么 |
| --- | --- | --- |
| 后端 | **FastAPI**（本项目原有） | 教室场景要能双击 `start.bat` 就跑起来；FastAPI 自带 OpenAPI 文档（`/docs`），验收脚本还能拿 `openapi.json` 做接口交叉检查 |
| ORM | **SQLAlchemy 2.0 async + aiosqlite** | 换库只改 `.env` 里的 `DATABASE__URL_OVERRIDE`，业务代码零改动 |
| 数据库 | **开发/教室：SQLite；集中部署：MySQL 8 / PostgreSQL** | 单文件、零运维、可随项目一起拷贝；两种方言的建表 SQL 都写在 `docs/student_error_logs.sql` 里 |
| 前端 | **原生 HTML + CSS + JS**（无框架） | 断网也能用；面板分栏、Markdown 渲染这些都有现成的小库，不需要 Vue 的运行时 |
| Markdown | **marked + DOMPurify**（本地 vendor） | 见第 5 节：AI 输出必须消毒后再 `innerHTML`，这是硬要求 |

**为什么错题本要单独建表，而不是挂在别的记录表上**

项目里原本还有一张 `tutor_records` 流水账（每次点按钮都记一条，含"没错误"的那些），
它唯一的读取方是页面左下角的「历史记录」列表。该功能与错题本职责重叠且没有复习价值，
已连同 `tutor_records` 表一起删除。这里保留当初分表的判断依据：

| 记法 | 记什么 | 读法 |
| --- | --- | --- |
| 流水账（已删除的 `tutor_records`） | 每次点按钮都记，含"没错误"的那些 | 「我最近看过哪些代码」 |
| `student_error_logs` | 错题本：只记真正出错的，字段面向复习与聚合 | 「我老是错在哪」 |

合并的代价：查「最近 8 条错题」要在流水账上按状态过滤；历史列表被"无错误"记录稀释；
按知识点聚合等于每次全表扫。所以错题本独立成表。

## 2. 数据库设计

完整 DDL（SQLite + MySQL + 常用查询）在 **`docs/student_error_logs.sql`**。
ORM 模型在 `app/models/error_log.py`，服务启动时 `init_db()` 会自动建表。

需求点名的 8 个字段全部具备，另加 6 个工程字段：

```
必需：id / student_id / code_snippet / language /
      error_type / knowledge_point / ai_feedback / created_at
补充：knowledge_points_json  一次可能涉及多个知识点，完整列表存 JSON
      knowledge_point        取列表第一条作为"主知识点"，用于 GROUP BY 聚合
                             （在 JSON 列上聚合需要数据库 JSON 函数，
                               SQLite 与 MySQL 写法不同；冗余一列后
                               聚合就是最普通的 GROUP BY，两个库都能跑）
      filename / source      来自哪个文件 / 是 diagnose 还是 check 产生的
      model / trace_id       排查"为什么这次结论不一样"
```

两条关键索引：

```sql
CREATE INDEX ix_student_error_logs_student_created ON student_error_logs (student_id, created_at);
CREATE INDEX ix_student_error_logs_student_kp      ON student_error_logs (student_id, knowledge_point);
```

- 第一条支撑主力查询「某学生最近 N 条错题」（按学生过滤 + 时间倒序）；
- 第二条支撑「某学生最常错的知识点」（按学生 + 知识点分组计数）。

**`student_id` 用字符串而不是外键**：单机部署下页面不再要求填学号，后端统一填
`local`（`app/api/v1/endpoints/tutor.py` 的 `_resolve_student_id()`），
请求里带 `X-Student-Id` 或 `student_id` 时按传进来的值记，不带就是 `local`——
列留着，将来接入统一认证时换成指向用户表的整数外键即可，
字符串列能同时容纳学号与 UUID。

## 3. 后端接口

### 3.1 规范接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/tutor/diagnose` | 诊断：查历史错题 → 拼提示词 → 调模型 → 有错则归档 → 返回上下两半屏的数据 |
| GET | `/api/v1/tutor/errors` | 错题本列表 + 易错知识点 Top 5 |
| DELETE | `/api/v1/tutor/errors/{id}` | 删除一条错题（**只能删自己的**） |
| POST | `/api/analyze` | 兼容别名，按需求文档的 JSON 契约 `{student_id, language, code_content}` |

`/diagnose` 走 multipart 表单（`code` / `filename` / `student_id` / `model_id` / `api_key`），
与项目里既有的 `/check`、`/comment`、`/fix` 完全一致，前端不用为这一个按钮单写一套提交逻辑；
学号同时支持 `X-Student-Id` 请求头（前端统一走请求头）。

**别名不重新实现业务逻辑**，而是直接 `await` 调用规范接口那个函数
（FastAPI 的路径函数本身就是普通 Python 函数）。理由：两条路径各写一份必然漂移，
最常见的后果是"网页上好好的、用脚本调就少了错题本归档"，而且**不会报错**。

### 3.2 请求 / 响应

```jsonc
// POST /api/analyze 请求体（需求文档的契约；student_id 可省，省略即 local）
{ "student_id": "local", "language": "python", "code_content": "def add(a,b):\n    return a-b\n" }

// 响应：上半屏 analysis + 下半屏 wrong_question_book，与提示词的输出模板一一对应
{
  "student_id": "local", "filename": "submitted.py",
  "language": "python", "language_label": "Python",
  "analysis": {
    "status": "error", "error_type": "逻辑错误",
    "message": "函数名叫 add，却用了减号。",
    "knowledge_points": ["函数返回值", "运算符使用"]
  },
  "wrong_question_book": {
    "history_summary": "你在「循环边界」上已经错了 3 次，是最需要补的地方。",
    "new_exercise": {
      "question_title": "实现 subtract 函数",
      "question_description": "写一个 subtract(a, b)，返回两数之差。",
      "hint": "注意参数的先后顺序，不要写反。"
    },
    "knowledge_explanation": "## 运算符\n\n```python\nreturn a + b\n```"
  },
  "history_count": 2,      // 本次喂给模型的历史错题条数
  "history_total": 3,      // 错题本当前总数（写库之后统计，与列表接口一致）
  "weak_points": [{ "knowledge_point": "循环边界", "count": 3 }],
  "logged": true,          // 这次错误是否已归档
  "error_log_id": 9, "model": "deepseek-chat", "trace_id": "..."
}
```

### 3.3 提示词实现（`app/agents/tutor_agent.py`）

- `DIAGNOSE_SYSTEM`：需求给的 System Prompt，**逐字使用**。测试
  `test_system_prompt_is_used_verbatim` 锁死了几处关键约束
  （两处禁止 markdown 代码块的强调、四条 Constraints），避免以后被"顺手优化"掉。
- `build_diagnose_user_prompt(...)`：按需求模板拼接 User Prompt。单独抽成函数，
  可以脱离大模型对拼接结果写断言。
- `format_error_history(records)`：把历史错题拍成"编号 + 中文字段名"的文本。
  模型对编号列表的遵循度明显高于嵌套 JSON；代码片段超过 1200 字符会首尾截断
  （8 条拼起来会挤爆上下文，而总结规律只需要看到出错的那几行）。
- 历史为空时**不放空白**，而是明确写「该学生暂无历史错题记录，这是他的第一次提交」
  ——留空会让模型自己编几条历史错题出来（真的会）。
- `normalize_diagnose_payload(...)`：把模型输出收敛成前端契约的形状。三处刻意设计：
  1. `status` 同义词收敛（`ok` / `通过` / `correct` → `success`），
     **收敛不了一律按 `error`**——把没错的误记成错题，学生顶多多做一道题；
     反过来漏掉真错题，错题本就失去意义了。
  2. 缺字段补默认值，前端就不用到处写 `data.wrong_question_book?.new_exercise?.hint || ''`。
  3. `TutorResult.parsed` 标志区分「代码没问题」与「模型跑偏了」。

### 3.4 三处最容易踩的地方（都写进了代码注释）

1. **历史错题必须在调用模型之前查**，且不含本次。先写库再查，模型会看到一条
   还没被分析的"本次错误"，逻辑上自相矛盾。
2. **只有 `status == "error"` 才写错题本**。代码没问题时也写，错题本会被
   "无错误"记录稀释，「易错知识点」统计直接失真。
3. **模型没返回可解析 JSON 时返回 502，而不是当成"无错误"**。后者会让一次 AI 跑偏
   被伪装成"你的代码很好"——这是这里最危险的一种静默失败。同时**不写错题本**，
   避免污染。

## 4. 前端改造

### 4.1 结构（`frontend/index.html`）

```
右侧 .pane.pane--split（flex 列，overflow: hidden）
├─ #analysisCard      上半屏：⑤ 分析结果（检测 / 注释 / 改错 / 诊断结论 四选一）
│   └─ .card__scroll  标题固定、内容自己滚动
├─ #resizerResultSplit  ⇕ 水平分隔条（可拖动、可用方向键、双击复位）
└─ #wrongBookCard     下半屏：⑥ 错题本 & 举一反三
    └─ .card__scroll  易错知识点条形图 / 历史总结 / 新题目（提示默认折叠）/ Markdown 解析 / 错题明细
```

高度用 CSS 变量控制：默认 `--analysis-h: 46%`（跟随窗口成比例），
用户拖过之后换成像素值并存进 `localStorage`（键 `ai-tutor.layout`）。

**注意别把 `--analysis-h` 声明在 `.pane--split` 上**：CSS 自定义属性会被就近作用域
遮蔽，JS 写在 `document.documentElement` 上的值就永远读不到，表现是"上下拖不动"。
正确写法是 `flex: 0 0 var(--analysis-h, 46%)`，让默认值当兜底而不是当覆盖。
`tools/check_frontend.py` 的 3.7 就是专门盯这一条的（把 bug 塞回去会失败）。

自适应分三档（`LAYOUT_TIERS = {wideMin: 1200, midMin: 900}`）：

| 视口宽度 | 列分隔条 | 右侧上下分隔条 |
| --- | --- | --- |
| ≥ 1200px | 两根都在 | 在 |
| 900–1199px | 只留左侧（右侧分析栏已足够宽） | 在 |
| < 900px | 全部隐藏，退回窄屏单列 | 在（上下分栏仍然可用） |

窗口尺寸变化时会重新 clamp 一遍像素高度，否则把窗口拖小以后，
之前存的像素值会把下半屏挤出屏幕外。

**为什么错题本要独立成下半屏**：上半屏的内容每点一次按钮就整块换掉，
而错题本是**跨次累积**的，学生需要它一直挂在眼前。放同一块里，一改代码就看不到了。

### 4.2 身份：单机不填学号

页面**不提供学号输入框**。单机部署一人一机，学号只会变成一道多余的必填门槛：
忘填就点不动「诊断」，而错题本本来就只服务这台机器上的这个人。

后端 `_resolve_student_id()` 统一兜底：请求带 `X-Student-Id` 或 `student_id` 就按传进来的记，
不带就是 `local`。列留在 `student_error_logs` 里，将来接统一认证不用改表结构。

这里与"缺学号返回 400 不兜底"是**两回事**：那是"该有而没有"，这是"本来就只有一个身份"。
两者都遵守同一条原则——不要静默地把多个学生的错题混成一本。

### 4.3 Markdown 渲染（`renderMarkdown`）

三步，缺一不可：

1. `marked.parse(source, {gfm: true, breaks: true})` —— Markdown → HTML；
2. **`DOMPurify.sanitize(html, {USE_PROFILES: {html: true}})` —— 消毒**；
3. `hljs.highlightElement(block)` —— 代码块上色，与页面其它代码区观感一致。

第 2 步是**硬要求，不是可选项**：这段 HTML 来自大模型，而模型的输入里含着
学生粘贴的代码——恶意代码可以借此注入 `<script>` 或 `onerror`，
在学生浏览器里执行。直接 `innerHTML` 就是 XSS。

两个库都放在 `frontend/vendor/`（本地文件），与 `highlight.js` 一样的理由：
教室可能没网，CDN 一挂下半屏就空白了。任何一个库不可用时**降级为转义后的纯文本**，
不白屏、也不把未消毒的 HTML 塞进 DOM。

## 5. 完整数据流

### 5.1 用户点「🎯 诊断 + 举一反三」到看到结果

```
[浏览器]  ① 点击 #btnDiagnose
              │
              ▼
          ② runDiagnose()
              ├─ setBusy(true) 禁用四个 AI 按钮（防连点重复计费）
              ├─ showResult('diagnose') 上半屏切到诊断块，标题徽章标「AI 诊断」
              └─ api('/diagnose', POST, codeFormData())
                    │  请求头：X-Session-Id（用户在页面上填的 Key 的会话号）
                    │  表单体：code / filename / model_id
                    ▼
[后端]    ③ POST /api/v1/tutor/diagnose          app/api/v1/endpoints/tutor.py
              ├─ _read_code()      取出代码与文件名（上传文件或表单文本，自动试编码）
              ├─ _resolve_language()  按后缀识别语言；识别不出 → 400
              ├─ _resolve_student_id(表单字段, X-Student-Id)  都没有 → "local"
              │
              ├─ ④ TutorService.recent_errors(student_id, limit=8)   ← 错题本表（时间倒序）
              ├─    format_error_history(history) → 「编号 + 中文标签」文本
              │     （没有历史时放入「这是第一次提交」的明确提示）
              │
              ├─ ⑤ _active_agent(...)  挑出这次用哪个模型 / 哪把 Key
              │     · 页面填了 Key → 从内存会话取出，现造客户端（用完即关）
              │     · 都没传 → 用 .env 里配的默认模型
              │
              ├─ ⑥ TutorAgent.diagnose(code, history_text=...)
              │     ├─ build_diagnose_user_prompt()  用需求模板拼 User Prompt
              │     ├─ LLMClient.chat([system=DIAGNOSE_SYSTEM, user=...])
              │     ├─ extract_json_object()  从模型输出里抠 JSON（容忍 ```json 围栏与前后废话）
              │     ├─ parsed=False → 上层返回 502 让学生重试，**不写错题本**
              │     └─ normalize_diagnose_payload()  status 同义词收敛、缺字段补默认值
              │
              ├─ ⑦ analysis.status == "error" ?
              │     是 → TutorService.save_error(...)  写入 student_error_logs
              │            （knowledge_points[0] 作为主知识点单独存一列，完整列表存 JSON）
              │            logged=true, error_log_id=...
              │     否 → 不写（避免"无错误"记录稀释错题本统计）
              │
              ├─ ⑧ count_errors() + weak_points()  ← 在写库**之后**统计，
              │     让返回值与前端刷新列表后看到的一致（否则会出现"5 条 / 6 条"两个数字）
              │
              └─ ⑨ 返回 { analysis, wrong_question_book, history_count, history_total,
                          weak_points, logged, error_log_id, model, trace_id }
                    ▼
[浏览器]  ⑩ renderDiagnose(data)   上半屏：结论徽章（通过/发现问题，红绿）+ 错误类型
                                   + 诊断说明 + 知识点标签 + 「已记入错题本」提示
          ⑪ renderWrongBook(data.wrong_question_book, data)
                                   下半屏：历史总结、新题目（提示默认折叠）、
                                   renderMarkdown() 渲染知识点解析
          ⑫ loadErrorBook()  GET /api/v1/tutor/errors?limit=20
                                   → 易错知识点条形图（宽度 = 次数/最高次数）
                                   → 历史错题明细（每条带「删除」）
                                   （重新拉一次，把刚归档的那条显示出来）
          ⑬ setBusy(false) + reclampLayout()
```

## 6. 边界与降级

| 情况 | 行为 |
| --- | --- |
| 请求没带身份 | 按 `local` 归档（单机部署的默认身份） |
| 语言识别不出 | 400，提示用 `.c` / `.java` / `.py` |
| 未配置模型 | 503 + 中文提示（去哪填 Key），与既有 AI 接口一致 |
| 模型输出不是 JSON | 502 让学生重试；**不写错题本** |
| 模型漏返回字段 | 后端补齐默认值，前端只处理"有值但为空" |
| 模型没给 Markdown 代码示例 | 只记一条 warning 提示，**不替它编内容** |
| 写错题本失败 | 只告警；`logged=false`，诊断结果照常返回，并如实告诉学生"归档失败" |
| 删除不存在的错题 | 404（student_id 作为过滤条件一起查，删不到别人那条） |
| 旧库缺列（升级上来的 `app.db`） | 启动时补列；读回来缺字段按默认值处理，不 500 |
| marked / DOMPurify 没加载 | 降级为转义后的纯文本 |
| 窄屏（≤899px） | 列分隔条隐藏，上下分栏仍可用；中间档（900–1199px）只保留右侧分隔条 |
